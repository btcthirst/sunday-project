# Документація для розробника (Passport Desk MVP)

Цей документ містить технічну інформацію про архітектуру, безпеку та робочий процес розробки проекту Passport Desk MVP.

## 1. Архітектурний огляд

Проект побудований на базі **Wails v2**, що поєднує потужність **Go** на серверній стороні та гнучкість **Vue.js** у фронтенді.

### 1.1 Backend (Go)
Backend організований за багатошаровою архітектурою:
- **App (`app.go`)**: Головна точка входу для Wails bindings. Обробляє сесії, автентифікацію та делегує бізнес-логіку сервісам.
- **Service Layer (`internal/services`)**: Містить бізнес-логіку застосунку (наприклад, `CitizenService`, `RegistrationService`). Взаємодіє з репозиторіями та забезпечує шифрування даних.
- **Repository Layer (`internal/repository`)**: Відповідає за доступ до даних (SQL запити). Використовує інтерфейси для забезпечення гнучкості та тестування.
- **Security Layer (`internal/security`)**: Надає інструменти для шифрування, хешування паролів та керування ключами.
- **Container (`internal/container`)**: Проста реалізація Dependency Injection. Збирає всі сервіси та репозиторії разом при ініціалізації.

### 1.2 Frontend (Vue.js 3)
- **Технології**: Composition API, Naive UI, Tailwind CSS.
- **Wails Runtime**: Взаємодія з Go відбувається через автоматично згенеровані JS-біндінги (`frontend/wailsjs/go`).
- **Структура**:
  - `views/`: Основні сторінки (Dashboard, CitizenList, CitizenForm і т.д.).
  - `components/`: Багаторазові компоненти.

## 2. Модель безпеки та шифрування

Безпека є ключовою частиною проекту. Реалізовано багаторівневий захист.

### 2.1 Шифрування бази даних
Весь файл бази даних (`passport_desk.db`) зашифрований за допомогою **SQLCipher (AES-256)**.
- При першому запуску генерується випадковий **Database Secret**.
- Цей секрет не зберігається у відкритому вигляді. Він загортається (encrypting) двома способами:
  1.  **User Wrapped**: Зашифрований паролем оператора (через PBKDF2).
  2.  **Master Wrapped**: Зашифрований випадковим Майстер-ключем.

### 2.2 Шифрування на рівні застосунку
Чутливі поля (паспортні дані, ІПН, телефон) додатково шифруються перед збереженням у БД.
- **Алгоритм**: AES-256-GCM.
- **Ключ**: Database Secret.
- Це забезпечує захист даних навіть у випадку, якщо база даних відкрита (наприклад, під час роботи застосунку).

## 3. База даних та міграції

### 3.1 SQLCipher
Використовується пакет `github.com/mutecomm/go-sqlcipher/v4`. З'єднання ініціалізується в `internal/database/db.go`.

### 3.2 Міграції
Міграції зберігаються в `internal/database/migrations.go` як масив SQL-інструкцій. Вони автоматично виконуються при створенні з'єднання з базою даних.

## 4. Розробка та збірка

### 4.1 Вимоги
- Go 1.24+
- Node.js & npm
- Wails CLI (`go install github.com/wailsapp/wails/v2/cmd/wails@latest`)

### 4.2 Запуск у режимі розробки
```bash
wails dev
```
Ця команда запускає backend та frontend з підтримкою hot-reload.

### 4.3 Збірка проекту
Для Windows:
```bash
wails build -platform windows/amd64
```
Для Linux:
```bash
wails build
```

## 5. Тестування

Тести поділені на модульні та інтеграційні.
- Модульні тести для безпеки: `internal/security/*_test.go`
- Тести репозиторіїв: `internal/repository/*_test.go` (використовують базу даних у пам'яті).

Запуск усіх тестів:
```bash
go test ./...
```

## 6. Важливі нотатки для розробників
- **Транзакції**: Завжди використовуйте транзакції в репозиторіях при зміні декількох пов'язаних таблиць (наприклад, при роботі зі зв'язками сімей).
- **Логування**: Використовуйте `log/slog` для структурованого логування. Не логуйте чутливі дані (паспортні дані, паролі).
- **Аудит**: Кожна зміна даних повинна супроводжуватися записом у `audit_log`.
