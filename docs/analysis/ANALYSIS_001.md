# Аналіз проєкту Passport Desk MVP

## Загальна інформація

**Назва проєкту:** Passport Desk MVP  
**Тип застосунку:** Десктопний застосунок для Windows/Linux  
**Технологічний стек:** Go (Wails v2) + Vue.js 3 + SQLCipher  
**Призначення:** Система обліку громадян та реєстрації за місцем проживання для паспортного столу

## 2. Безпека

### 2.1 Рівні шифрування

Проєкт реалізує **дворівневе шифрування**:

#### Рівень 1: Шифрування файлу БД (SQLCipher)
- Алгоритм: **AES-256**
- Ключ генерується з пароля оператора через **PBKDF2**
- Параметри: 100,000 ітерацій, SHA-256
- Salt зберігається в окремому файлі `db.salt`

#### Рівень 2: Шифрування полів (Application layer)
Зашифровані поля:
- Серія та номер паспорта
- ІПН/РНОКПП
- Телефон

Алгоритм: **AES-256-GCM**

### 2.2 Автентифікація
- Хешування паролів: **bcrypt** (cost factor: 12)
- Автоблокування після 5 хвилин неактивності
- Сесійне управління з автоматичним очищенням ключів

### 2.3 Аудит
- Повне логування всіх операцій (CREATE, READ, UPDATE, DELETE)
- Запис: оператор, дата/час, тип операції, опис

### 2.4 Оцінка безпеки

**Сильні сторони:**
- ✅ Дворівневе шифрування
- ✅ Правильне використання bcrypt та PBKDF2
- ✅ Шифрування чутливих полів на рівні застосунку
- ✅ Автоматичне блокування при неактивності
- ✅ Повний аудит-лог

**Потенційні ризики:**
- ⚠️ Втрата пароля = втрата доступу до всіх даних
- ⚠️ Salt зберігається у відкритому файлі (хоча це стандартна практика)
- ⚠️ Відсутність багатофакторної автентифікації

## 4. База даних

### 4.1 Структура таблиць

#### operators
- Зберігання облікових записів операторів
- Поля: id, username, password_hash, full_name, created_at

#### citizens
- Основна таблиця громадян
- 17+ полів, включаючи зашифровані
- Підтримка soft delete

#### registrations
- Реєстрації за адресою
- Зв'язок з громадянами (foreign key)
- Історія з is_active флагом

- Зв'язки між громадянами
- UNIQUE constraint на пару (citizen_id, member_id)

- Журнал всіх операцій

## 7. Критичні моменти

### 7.1 Безпека

**Високий ризик:**
1. **Втрата пароля** - немає механізму відновлення
   - Рекомендація: Додати майстер-ключ або recovery questions

2. **Salt у відкритому файлі** - хоча це стандартна практика, потенційний вектор атаки
   - Рекомендація: Розглянути використання TPM/Secure Enclave

**Середній ризик:**
3. **Відсутність rate limiting** на логін
   - Рекомендація: Додати обмеження спроб входу

4. **Логування чутливих даних** - потенційно можливе
   - Рекомендація: Аудит всіх місць логування

### 7.2 Продуктивність

**Проблемні зони:**
1. **Пошук по зашифрованих полях** - O(n) складність
   - Всі записи завантажуються в пам'ять для дешифрування
   - Рекомендація: Розглянути searchable encryption

2. **Експорт великих обсягів** - потенційно OOM
   - Рекомендація: Streaming export

3. **Відсутність кешування** - кожен запит до БД
   - Рекомендація: Кешування частих запитів

### 7.3 Надійність

**Проблеми:**
1. **Backup не тестується** - відновлення з backup не перевірено
2. **Транзакції не всюди** - потенційна inconsistency
3. **Відсутність graceful shutdown** - можлива втрата даних
